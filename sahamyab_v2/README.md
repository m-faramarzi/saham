# خزندهٔ مستقل سهامیاب ـ نسخهٔ ۲

این پوشه یک پیاده‌سازی مستقل است و هیچ‌یک از کدهای قبلی پروژه را تغییر نمی‌دهد.

## رفتار اصلی

- نمادها ابتدا بر اساس قدیمی‌ترین `last_run_at` مرتب می‌شوند. برای داده‌های قدیمی که این فیلد را ندارند، `last_seen` استفاده می‌شود.
- اگر زمان اجرا برابر باشد، نمادی که `last_run_tweet_count` بیشتری دارد زودتر اجرا می‌شود.
- برای هر نماد، صفحه‌بندی تا رسیدن به `hasMore=false` ادامه دارد. محدودیت اختیاری صفحات باعث ثبت ناقص داده نمی‌شود و اجرای آن نماد را ناموفق می‌کند.
- همهٔ توییت‌های دریافتی، حتی توییت‌های قدیمی، در SQLite به‌صورت upsert ذخیره می‌شوند؛ بنابراین لایک، کامنت و سایر فیلدهای تغییرکرده به‌روز می‌شوند.
- `last_run_tweet_count` فقط شناسه‌هایی را می‌شمارد که قبلاً برای همان نماد دیده نشده‌اند.
- تمام هشتگ‌های متن اصلی و متن والد کشف می‌شوند. هیچ هشتگ قدیمی حذف یا فیلتر نمی‌شود.
- فایل `symbols.json` به‌شکل اتمیک نوشته می‌شود و همهٔ فیلدهای ناشناختهٔ قبلی حفظ می‌شوند.
- اگر دریافت همهٔ صفحات شکست بخورد، هیچ توییت یا وضعیت موفقی برای آن نماد ثبت نمی‌شود.
- هر نمادی که در یکی از صفحات شکست بخورد، دقیقاً یک بار در انتهای همان batch دوباره امتحان می‌شود.
- پاسخ‌های 403 و 429 فاصلهٔ بین نمادها را به‌صورت نمایی و با jitter تصادفی افزایش می‌دهند. هر اجرای موفق سطح فشار را یک پله کاهش می‌دهد.

## آماده‌سازی داده‌های قبلی

برای اینکه توییت‌های snapshotهای قبلی در اولین اجرای نسخهٔ جدید، «جدید» شمرده نشوند، یک‌بار import را اجرا کنید:

```powershell
python -m sahamyab_v2 import-legacy
```

اجرای دوبارهٔ import امن است و دادهٔ تکراری ایجاد نمی‌کند.

## اجرای crawler

```powershell
python -m sahamyab_v2 crawl --limit 150
```

`--limit 0` همهٔ هشتگ‌ها را انتخاب می‌کند. `--max-pages 0`، که مقدار پیش‌فرض است، تمام صفحات ممکن را می‌خواند. پایگاه داده در `sahamyab_v2/data/sahamyab.sqlite3` ساخته می‌شود و مسیرها از طریق آرگومان‌های CLI قابل تغییرند.

تنظیمات پیش‌فرض انتظار تطبیقی عبارت‌اند از شروع از ۱۵ ثانیه، سقف ۳۰۰ ثانیه و jitter برابر ۲۵ درصد. برای نمونه:

```powershell
python -m sahamyab_v2 crawl --limit 150 `
  --backoff-base 20 --backoff-max 240 --backoff-jitter 0.30
```

این مقادیر به‌ترتیب با `--backoff-base`، `--backoff-max` و `--backoff-jitter` قابل تغییرند. سقف فقط بر انتظار تطبیقی اعمال می‌شود و retry هر نماد همچنان حداکثر یک بار است.

## اجرای GitHub Actions

workflow موجود در `.github/workflows/crawl.yml` برای نسخهٔ جدید تنظیم شده است:

- پیش از crawl تست‌ها را اجرا می‌کند.
- آخرین SQLite و نسخهٔ هماهنگ `symbols.json` را از artifact با نام `sahamyab-v2-state` بازیابی می‌کند.
- اگر artifact هنوز وجود نداشته باشد، یک بار دیتابیس را از snapshotهای Git مقداردهی می‌کند.
- پس از اجرای ۱۵۰ هشتگ، دیتابیس جدید را artifact می‌کند و فقط `symbols.json` را commit می‌کند.
- artifactهای قدیمی را پس از موفقیت حذف می‌کند تا فضای Actions بی‌دلیل رشد نکند.
- concurrency مانع اجرای هم‌زمان دو crawler روی یک state می‌شود.

دیتابیس عمداً داخل Git commit نمی‌شود. runnerهای GitHub موقت هستند و artifact، state را بین اجراها منتقل می‌کند. در اجرای دستی، ورودی `limit` قابل تغییر است؛ اجرای زمان‌بندی‌شده مقدار ۱۵۰ را استفاده می‌کند.

## تعریف «توییت جدید»

یک توییت زمانی برای نماد جدید است که رابطهٔ `(symbol, tweet_id)` قبلاً در جدول `symbol_tweets` وجود نداشته باشد. خود توییت فقط یک‌بار در جدول `tweets` نگهداری و در اجراهای بعدی با پاسخ تازهٔ API به‌روزرسانی می‌شود.
